# Bombsite Retake / 爆破点夺回

## 目标

使用 Three.js 制作一款完整、精致、原生运行于浏览器的 3D 战术第一人称射击游戏 **Bombsite Retake**。它以 **《Counter-Strike 2》**广为人知的爆破点夺回循环作为共同玩法参照，但所有名称、地图、武器模型、声音、纹理、角色和界面资产都必须原创。

玩家作为处置人员进入一处紧凑的工业设施。装置已经被安放，并由两名敌方 Bot 防守。玩家要从两条可行路线中选择一条抵达爆破点，在交火中存活、击败两名守军以控制现场，然后持续按住交互键，在 90 秒倒计时结束前完成拆除。两名守军全部被击败前，拆除进度必须始终保持为零；清场只是解锁拆除，不能替代拆除步骤。

## 运行完成合同

以下功能清单定义目标作品与质量评测标准，不要求 Agent 为每一项做穷尽式自证。满足以下运行检查后即可完成 Goal：

- `npm run build` 成功，并把静态生产构建输出到 `dist/`。
- 生产构建能在 1440 x 900 和 390 x 844 下加载，显示可见、非空白、可交互的 3D 场景；受测流程的横向溢出不超过 2 个 CSS 像素，且没有未捕获页面异常或 `console.error`。
- 每个视口各做一次简短冒烟检查，确认游戏可以进入主要游玩状态、一个主要控制会改变可观察的游戏状态，并且重开能返回有效初始状态。

检查必须保持短时且有界。只有检查失败并完成相关修复后才重跑，通过后立即停止。不要为了证明完成而编写自动驾驶器，也不要反复跑完整胜利、失败、任务、对局、比赛、营业、整夜、关卡、任务链、Boss 战或解谜流程。这些路径以及功能完整度、平衡、打磨和游戏手感由提交后的评测决定；不足会影响结果，但不要求 Agent 在运行检查通过后继续自测。只报告实际执行过的检查。

## 目标游戏系统

- 第一人称相机、带碰撞的移动、行走、冲刺、蹲伏、跳跃、鼠标锁定瞄准和触摸视角控制。
- 一把清晰可用的步枪，包含命中扫描射击、弹匣和备弹、换弹时间、后坐力或散布、枪口反馈、命中反馈，以及换弹期间禁止射击。
- 两名分别巡逻或架守不同角度的 Bot，能按距离和视线发现玩家，会利用掩体或换位，以有预兆且非必中方式射击，并可被击败。
- 一处经过设计的爆破点，两条接近路线在最终进入爆破点前保持拓扑分离，并具有不同的暴露或掩体取舍；同时包含可识别地标、避免出生即被射击的布局，且不存在无法到达的位置。
- 已安放装置，具有逐渐增强的声音或视觉紧迫感、90 秒倒计时、清场后才解锁拆除、交互距离、被打断的持续拆除进度，以及明确的拆除完成状态。
- 生命值、弹药、计时、存活敌人数、拆除进度、受击方向、准星、当前目标、胜利和失败界面。
- 桌面端键盘鼠标控制，以及可用的手机双摇杆和明确的射击、换弹、蹲伏、交互按钮。
- 最低输入约定：桌面端向前移动必须响应 W 或上方向键之一；手机端主要移动摇杆必须位于屏幕左下控制区域。

## 执行检查点

1. 建立地图、碰撞、相机、移动、两条路线，以及桌面和手机输入。
2. 完成步枪、伤害、两名 Bot、视线行为、掩体和公平战斗。
3. 完成装置倒计时、持续拆除逻辑、完整状态流、HUD 与重开。
4. 提升枪械手感、空间声音或视觉提示、光照、材质、命中特效和战术可读性。
5. 最后一次相关修改后执行一次构建，再在 1440 x 900 和 390 x 844 下完成有界运行冒烟检查。只需在完成前修复实际观察到的构建、启动、空白画面、输入、重开、异常或布局故障。

## 质量目标

- 玩家无需猜测即可识别爆破点、倒计时压力、敌人、掩体和交互状态。
- Bot 具有威胁，但不能穿过实体几何射击，也不能使用无法躲避的完美瞄准。
- 玩家在交互区外、死亡时、仍有守军存活时或倒计时结束后，拆除进度都不能开始或增加；松开交互键或离开区域会重置持续按住进度。
- 鼠标锁定必须有明确的恢复方式；触摸控制不能遮挡准星和关键 HUD。
- 页面缩放和可见性变化不能破坏有效状态或产生幽灵输入。

- 两个评测视口的页面横向溢出都不得超过 2 个 CSS 像素，受测流程不得产生未捕获页面异常或 `console.error` 输出。

## 运行时检查合同

提供随游戏进程更新、可 JSON 序列化的 `window.__WEB3DGAMEBENCH__` 对象，至少包含：

该对象从首个渲染帧起就必须字段完整并通过 schema，开始前反映可玩的初始状态；重新开始后，除 `restartCount` 外必须回到同一状态。游玩中按 `R` 必须立即重新开始，手机模式必须提供文本、`aria-label` 或 title 明确写有“重开”或“Restart”的可见控件；任一路径都只让 `restartCount` 增加一次。

- `phase`：`ready`、`playing`、`paused`、`won` 或 `lost`；
- `score`：有限数值；
- `player`：由有限数值组成的 `{ x, y, z }`；
- `health`：0 到 100 的有限数值；
- `ammo`：非负整数；
- `reserveAmmo`：非负整数；
- `enemiesAlive`：0 到 2 的整数；
- `bombSecondsRemaining`：非负有限数值；
- `defuseProgress`：0 到 1 的有限数值；
- `defuseStartedAfterClear`：布尔值，只能在两名守军都被击败后，合法拆除进度首次增加时变为 `true`；
- `seed`：`28417`；
- `restartCount`：非负整数。

可以增加字段，但不得暴露只供评测器使用的捷径或可调用函数。
