# Dinner Rush / 晚餐冲刺

## 目标

使用 Three.js 制作一款完整、精致、原生运行于浏览器的 3D 厨房协作游戏 **Dinner Rush**。它以 **《Overcooked》**广为人知的跨工位食材处理、烹饪、装盘、订单计时、失误和计分循环作为共同玩法参照。名称、厨师、厨房布局、菜谱、食物模型、声音、图标和界面资产都必须原创。

玩家在一间紧凑餐厅厨房内控制两名厨师，并可随时切换。四分钟营业时间内，需要从三类菜谱中制作并交付五份合法菜品。在打烊前完成五份有效上菜，且每名厨师都至少为一份最终被接受的菜品做出一次可见的备餐或运输贡献，才算胜利；时间结束时少于五份则失败。烧焦和错误菜品会损失时间或分数，但不能造成无法恢复的死局。

## 运行完成合同

以下功能清单定义目标作品与质量评测标准，不要求 Agent 为每一项做穷尽式自证。满足以下运行检查后即可完成 Goal：

- `npm run build` 成功，并把静态生产构建输出到 `dist/`。
- 生产构建能在 1440 x 900 和 390 x 844 下加载，显示可见、非空白、可交互的 3D 场景；受测流程的横向溢出不超过 2 个 CSS 像素，且没有未捕获页面异常或 `console.error`。
- 每个视口各做一次简短冒烟检查，确认游戏可以进入主要游玩状态、一个主要控制会改变可观察的游戏状态，并且重开能返回有效初始状态。

检查必须保持短时且有界。只有检查失败并完成相关修复后才重跑，通过后立即停止。不要为了证明完成而编写自动驾驶器，也不要反复跑完整胜利、失败、任务、对局、比赛、营业、整夜、关卡、任务链、Boss 战或解谜流程。这些路径以及功能完整度、平衡、打磨和游戏手感由提交后的评测决定；不足会影响结果，但不要求 Agent 在运行检查通过后继续自测。只报告实际执行过的检查。

## 目标游戏系统

- 能清楚看到工位和两名厨师的倾斜 3D 厨房相机、带碰撞的厨师移动和明确的当前厨师标记。
- 随时切换两个位置独立的厨师。每名厨师最多携带一种食材、工具、盘子或成品，并且都必须为至少一份最终被接受的菜品完成真实的备餐或运输动作。
- 食材箱、至少两个台面、切菜板、锅或煎台、盘子堆、出餐口、垃圾桶和水槽。交互目标必须高亮或以其他方式明确显示。
- 三种具有可见步骤要求的菜谱：
  - 田园沙拉：切好的番茄和叶菜装盘；
  - 蘑菇汤：三份切好的蘑菇入锅煮熟并装盘；
  - 铁板拼盘：切好的鱼和土豆一起烹饪并装盘。
- 耗时切菜、带进度的耗时烹饪、完成后的烧焦窗口、丢弃毁坏食物、上菜后返回脏盘，以及再次使用前的耗时清洗。
- 确定性订单队列，显示菜谱、剩余耐心、后续订单、成功交付、菜品拒绝、小费或分数、连击和营业计时。
- 五份交付胜利、时间结束失败、暂停、重开，并保证不会因盘子耗尽或丢弃食材形成不可恢复状态。
- 桌面键盘控制，以及可用的手机移动、切换厨师、拾取或放置或交互和动作控制。
- 最低输入约定：桌面端向前移动必须响应 W 或上方向键之一；手机端主要移动区必须位于屏幕左下控制区域。

## 执行检查点

1. 建立厨房布局、相机、两名厨师、碰撞、切换、响应式输入、携带、台面和工位选取。
2. 完成食材供应、切菜、烹饪、烧焦、装盘、洗盘、垃圾和三种菜谱状态机。
3. 完成确定性订单、耐心、验证、交付、计分、连击、计时、五单胜利、失败和重开。
4. 提升食物与工位可读性、动画、进度反馈、厨房光照、特效、紧迫提示和 UI 层级。
5. 最后一次相关修改后执行一次构建，再在 1440 x 900 和 390 x 844 下完成有界运行冒烟检查。只需在完成前修复实际观察到的构建、启动、空白画面、输入、重开、异常或布局故障。

## 质量目标

- 玩家能看到每名厨师携带的物品和所有正在工作的烹饪工位状态。
- 错误、不完整、生食或烧焦菜品会被一致拒绝，并明确说明原因。
- 控制另一名厨师时，烹饪进度和烧焦危险仍然清晰可读。
- 所需订单必须能在提供的工位、食材、盘子与时间平衡内完成。
- 触摸控制不能遮挡正在使用的工位、订单卡片或当前厨师。

- 两个评测视口的页面横向溢出都不得超过 2 个 CSS 像素，受测流程不得产生未捕获页面异常或 `console.error` 输出。

## 运行时检查合同

提供随游戏进程更新、可 JSON 序列化的 `window.__WEB3DGAMEBENCH__` 对象，至少包含：

该对象从首个渲染帧起就必须字段完整并通过 schema，开始前反映可玩的初始状态；重新开始后，除 `restartCount` 外必须回到同一状态。游玩中按 `R` 必须立即重新开始，手机模式必须提供文本、`aria-label` 或 title 明确写有“重开”或“Restart”的可见控件；任一路径都只让 `restartCount` 增加一次。

- `phase`：`ready`、`playing`、`paused`、`won` 或 `lost`；
- `score`：有限数值；
- `activeChef`：`0` 或 `1`；
- `chefs`：两个 `{ x, y, z, carrying }` 对象，位置为有限数值，`carrying` 为字符串或 `null`；
- `serviceSecondsRemaining`：非负有限数值；
- `ordersDelivered`：0 到 5 的整数；
- `chef0AcceptedContributions`：0 到 5 的整数，统计厨师 0 做出真实备餐或运输贡献且最终被接受的菜品数，每份菜对该厨师最多计一次；
- `chef1AcceptedContributions`：0 到 5 的整数，按同样规则统计厨师 1；
- `activeOrders`：非负整数；
- `dirtyPlates`：非负整数；
- `burnedItems`：非负整数；
- `combo`：非负整数；
- `seed`：`104729`；
- `restartCount`：非负整数。

可以增加字段，但不得暴露只供评测器使用的捷径或可调用函数。
