# Ashen Duel / 灰烬决斗

## 目标

使用 Three.js 制作一款完整、精致、原生运行于浏览器的 3D 第三人称 Boss 战游戏 **Ashen Duel**。它以 **《艾尔登法环》**广为人知的锁定目标、体力管理、翻滚时机、治疗、攻击承诺和可读 Boss 招式循环作为共同玩法参照。名称、角色、竞技场、招式、动画、特效、声音、图标和界面资产都必须原创。

玩家进入一座破败的圆形竞技场，与一名守护者 Boss 战斗。Boss 有两个阶段，整场战斗至少包含四种不同且有预兆的攻击。玩家将 Boss 生命值降为零即胜利，玩家死亡即失败。不得用额外关卡、菜单或成长系统掩盖未完成的决斗本体。

## 运行完成合同

实现下述游戏。`npm run build` 成功并生成 `dist/` 后，Goal 即完成。

不要编写或运行浏览器自动化、自动化运行检查、自动驾驶器或完整通关流程。运行表现、响应式适配、功能完整度、平衡、打磨和游戏手感由提交后的评测检查。只报告实际执行过的构建。

## 目标游戏系统

- 第三人称移动、碰撞、环绕相机、手动回正，以及带可见标记的锁定。
- 攻击和翻滚会消耗体力；体力不足时禁止动作，消耗后短暂停止恢复，并以可读速度再生。
- 轻击、较慢但伤害更高的重击、带短暂无敌窗口的翻滚、受击反应，以及不能全部瞬间取消的动作。
- 三次有限治疗，使用过程可以被打断或惩罚，并且不能超过最大生命值。
- 一个具有追击、距离控制、朝向、伤害、硬直或反应反馈和死亡状态的 Boss，至少包含快速攻击、延迟重击、范围攻击，以及突进或投射物四类招式。
- Boss 生命低于 50% 时发生明确阶段变化，实际改变节奏、连段、攻击距离或场地压力，而不只是换颜色。
- 玩家生命与体力、Boss 生命与阶段、治疗次数、锁定状态、动作提示、胜利、失败和重开界面。
- 桌面键盘与指针控制，以及可用的手机移动、相机、锁定、轻击、重击、翻滚和治疗控制。
- 最低输入约定：桌面端向前移动必须响应 W 或上方向键之一；手机端主要移动区必须位于屏幕左下控制区域。

## 执行检查点

1. 建立竞技场、玩家移动、碰撞、相机、锁定与响应式输入。
2. 完成体力、玩家动作、命中窗口、无敌、伤害、治疗与反馈。
3. 完成 Boss 状态机、四种攻击、前摇、收招窗口、阶段转换和平衡。
4. 完成 HUD、开始与胜负重开流程、视觉风格、光照、特效、相机反馈，以及可选声音。
5. 最后一次相关修改后执行一次 `npm run build`。成功生成 `dist/` 后立即结束，运行表现由提交后的评测检查。

## 质量目标

- 伤害只在定义好的攻击窗口发生，并尊重翻滚无敌时间。
- 前摇、攻击生效和收招三个阶段在视觉上可区分。
- 在竞技场边缘或双方交错时，锁定不能让相机失去控制。
- 体力和治疗决策必须有意义，同时初始状态允许公平获胜。
- 触摸控制在战斗中保持可触达，不能缩放或跳位。

- 在 1440 x 900 和 390 x 844 下，页面横向溢出不得超过 2 个 CSS 像素，运行时不得产生未捕获页面异常或 `console.error` 输出。

该对象从首个渲染帧起就必须字段完整并通过 schema，开始前反映可玩的初始状态；重新开始后，除 `restartCount` 外必须回到同一状态。游玩中按 `R` 必须立即重新开始，手机模式必须提供文本、`aria-label` 或 title 明确写有“重开”或“Restart”的可见控件；任一路径都只让 `restartCount` 增加一次。

- `player`：由有限数值组成的 `{ x, y, z }`；

- `bossHealth`：0 到 100 的有限数值；
