# Linked Chamber / 联结密室

## 目标

使用 Three.js 制作一款完整、精致、原生运行于浏览器的 3D 第一人称空间解谜游戏 **Linked Chamber**。它以 **《Portal 2》**广为人知的成对传送门穿越、动量重定向、方块、地面开关与出口门解谜循环作为共同玩法参照。名称、房间几何、装置设计、材质、声音、文字和界面资产都必须原创。

制作一个经过编排的测试密室，包含起始平台、低处深坑、至少四块标记为可放置传送门的墙面、一个可搬运能量方块、一个压力地板开关和一扇锁定出口。玩家必须放置蓝色和琥珀色传送门，通过联结的门对穿越空间，取回并运输方块，让开关保持受压，最后抵达出口。

## 完成合同

只有同时满足以下条件，目标才算完成：

- 传送门放置、成对视图、玩家穿越、方块穿越、搬运、开关、门状态、坠落恢复、胜利和重开全部可用。
- 密室具有一种必须使用传送门和方块的设计解法，不能直接步行到出口通关。
- 传送变换能保持合理的出口朝向和动量，不会引发反复进出循环。
- 生产构建成功，并在两个规定视口完整解开了谜题。

不要在画出两块传送门颜色矩形后停下。必须继续做到联结空间、穿越、物体交互和谜题解法能够协同工作。

## 必需游戏系统

- 第一人称移动、碰撞、重力、跳跃、鼠标锁定视角、触摸视角，以及跌出密室后的安全重生。
- 两个独立传送门操作，只能在标记为兼容的墙面放置蓝色或琥珀色门，非法命中应被拒绝，同色新门替换旧门。
- 每个已放置传送门必须显示其配对位置的实时或可信更新视图，而不是不透明纯色平面。
- 玩家和方块都能双向穿过已联结门对。位置、朝向和动量应一致变换，并通过冷却或方向穿越检测避免振荡。
- 一个可以拾取、在眼前搬运、释放、掉落、穿过传送门并放到压力开关上的方块。
- 开关能响应方块重量，以可见方式给门供能，并在方块移走后释放。只有门保持开启时进入出口才获胜。
- 准星、传送门合法性反馈、门状态、交互提示、开关到门的连接、目标、胜利、失败或恢复，以及重开界面。
- 桌面键盘与指针控制，以及可用的手机移动、视角、跳跃、交互、蓝门和琥珀门控制。

## 执行检查点

1. 建立密室、玩家控制器、碰撞、重力、相机、坠落恢复与响应式输入。
2. 完成合法放置、成对渲染、传送变换和稳定的玩家穿越。
3. 完成方块搬运与穿越、开关、供能门、设计解法、胜利与重开。
4. 提升空间提示、材质、光照、门边缘、连接反馈、交互动画和 UI 清晰度。
5. 在 1440 x 900 和 390 x 844 下完整解谜，并测试非法放置、重复穿越、方块掉落、缩放和恢复。

## 质量门槛

- 传送门视图必须对应配对位置，不能在相机移动后保持静止旧画面。
- 穿越不能把玩家卡进几何体、意外反转控制，或造成立即往返传送。
- 非法表面必须与可放置传送门的表面明确不同。
- 方块在合理失误后仍可找回，或者密室提供明确重置方式。
- 触摸控制能够放置两扇门并操作方块，且不会发生界面遮挡。

## 运行时检查合同

提供随游戏进程更新、可 JSON 序列化的 `window.__WEB3DGAMEBENCH__` 对象，至少包含：

- `phase`：`ready`、`playing`、`paused`、`won` 或 `lost`；
- `score`：有限数值；
- `player`：由有限数值组成的 `{ x, y, z }`；
- `bluePortalPlaced`：布尔值；
- `amberPortalPlaced`：布尔值；
- `portalTraversals`：非负整数；
- `cubeHeld`：布尔值；
- `cubeOnSwitch`：布尔值；
- `doorOpen`：布尔值；
- `seed`：`64891`；
- `restartCount`：非负整数。

可以增加字段，但不得暴露只供评测器使用的捷径或可调用函数。

## 约束与最终证据

使用提供的 Three.js 依赖和起始工具链。运行时不得请求网络，不得获取额外包或外部资产。全部代码和生成资产必须保留在工作区内。`npm run build` 必须把静态生产构建输出到 `dist/`。完成前如实报告构建结果，以及桌面端和手机端从开始到出口的完整解谜结果。
