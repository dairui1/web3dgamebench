# Frontier Command / 边境指挥

## 目标

使用 Three.js 制作一款完整、精致、原生运行于浏览器的 3D 即时战略游戏 **Frontier Command**。它以 **《魔兽争霸 III》**广为人知的单位选择、资源采集、基地建造、部队生产、下达命令和进攻敌方基地循环作为共同玩法参照。名称、阵营、单位、建筑、地形、声音、图标和界面资产都必须原创。

玩家在一张紧凑战场上以一座主堡和三名工人开局，地图包含木材与矿石。采集资源，建造一座兵营，训练至少三名士兵，抵挡一次敌方突袭，然后摧毁敌方主堡。敌方主堡被摧毁即胜利，己方主堡被摧毁即失败。

## 运行完成合同

以下功能清单定义目标作品与质量评测标准，不要求 Agent 为每一项做穷尽式自证。满足以下运行检查后即可完成 Goal：

- `npm run build` 成功，并把静态生产构建输出到 `dist/`。
- 生产构建能在 1440 x 900 和 390 x 844 下加载，显示可见、非空白、可交互的 3D 场景；受测流程的横向溢出不超过 2 个 CSS 像素，且没有未捕获页面异常或 `console.error`。
- 每个视口各做一次简短冒烟检查，确认游戏可以进入主要游玩状态、一个主要控制会改变可观察的游戏状态，并且重开能返回有效初始状态。

检查必须保持短时且有界。只有检查失败并完成相关修复后才重跑，通过后立即停止。不要为了证明完成而编写自动驾驶器，也不要反复跑完整胜利、失败、任务、对局、比赛、营业、整夜、关卡、任务链、Boss 战或解谜流程。这些路径以及功能完整度、平衡、打磨和游戏手感由提交后的评测决定；不足会影响结果，但不要求 Agent 在运行检查通过后继续自测。只报告实际执行过的检查。

## 目标游戏系统

- 高位视角相机，具有边缘或按键平移、拖拽平移、有限缩放、地图边界，以及触摸手势或明确的手机相机控制。
- 点击或触摸选择、桌面端拖框多选、可见选中状态、选择信息，以及右键或明确动作命令完成移动、采集、建造和攻击。
- 三名开局工人，能从至少四个木材点和三个矿石点采集，有限携带资源，返回主堡交付，并继续原工作。
- 基于网格的合法兵营放置，带可见预览、阻挡或资源不足反馈、建造时间与花费，并可取消或安全拒绝非法位置。
- 兵营生产队列，以资源和可见时间训练士兵。最终进攻需要至少三名已训练士兵才具有实际可行性。
- 友军和敌军具有移动、选取目标、攻击距离、冷却、伤害、生命、死亡、基础分离和避障寻路。
- 敌方基地包含一座主堡、两名防守者，以及一次定时进攻玩家的突袭。敌方主堡在对局开始前不能提前受击。
- 木材、矿石、人口、选择、建造动作、生产队列、生命条、当前目标、警报、胜利、失败和重开界面。
- 桌面指针与键盘控制，以及可用的手机选择、相机、移动或攻击、采集、建造和生产控制。
- 最低输入约定：桌面端相机向前平移必须响应 W 或上方向键之一；手机端必须能直接在战场上用手势平移相机，或提供明确可见的相机控制。

## 执行检查点

1. 建立战场、相机、选择、命令、导航网格、响应式输入和双方基地。
2. 完成工人、资源点、携带、交付、经济 UI 和稳定重复采集。
3. 完成兵营放置与施工、生产队列、士兵、战斗、敌方守军和定时突袭。
4. 完成平衡、胜负与重开、动作反馈、生命和选择 UI、经过设计的地形、地标、材质与特效。
5. 最后一次相关修改后执行一次构建，再在 1440 x 900 和 390 x 844 下完成有界运行冒烟检查。只需在完成前修复实际观察到的构建、启动、空白画面、输入、重开、异常或布局故障。

## 质量目标

- 下达命令后立即出现可见确认，单位能够抵达合理合法的目的地。
- 工人未完成采集与交付步骤时不能增加资源。
- 建筑不能与单位、资源、障碍、其他建筑或地图边界重叠。
- 敌方进攻能制造压力，但不能早于玩家形成基础应对能力。
- 手机端必须提供全部命令，不能依赖右键或悬停。

- 两个评测视口的页面横向溢出都不得超过 2 个 CSS 像素，受测流程不得产生未捕获页面异常或 `console.error` 输出。

## 运行时检查合同

提供随游戏进程更新、可 JSON 序列化的 `window.__WEB3DGAMEBENCH__` 对象，至少包含：

该对象从首个渲染帧起就必须字段完整并通过 schema，开始前反映可玩的初始状态；重新开始后，除 `restartCount` 外必须回到同一状态。游玩中按 `R` 必须立即重新开始，手机模式必须提供文本、`aria-label` 或 title 明确写有“重开”或“Restart”的可见控件；任一路径都只让 `restartCount` 增加一次。

- `phase`：`ready`、`playing`、`paused`、`won` 或 `lost`；
- `score`：有限数值；
- `camera`：由有限数值组成的 `{ x, y, z }`；
- `wood`：非负整数；
- `ore`：非负整数；
- `selectedUnits`：非负整数；
- `workersAlive`：0 到 3 的整数；
- `soldiersAlive`：非负整数；
- `soldiersTrained`：非负整数，记录兵营已经完成训练的士兵总数；
- `barracksBuilt`：布尔值；
- `raidResolved`：布尔值，仅在定时敌袭确实发生且已无敌袭单位存活时变为 true；
- `playerKeepHealth`：0 到 100 的有限数值；
- `enemyKeepHealth`：0 到 100 的有限数值；
- `seed`：`91373`；
- `restartCount`：非负整数。

可以增加字段，但不得暴露只供评测器使用的捷径或可调用函数。

## 约束与最终证据

使用提供的 Three.js 依赖和起始工具链。运行时不得请求网络，不得获取额外包或外部资产。全部代码和生成资产必须保留在工作区内。`npm run build` 必须把静态生产构建输出到 `dist/`。完成前如实报告生产构建结果和两个视口的有界冒烟检查。无需也不要求提供完整胜负或端到端通关证据。
