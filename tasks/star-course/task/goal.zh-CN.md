# Star Course / 星之赛道

## 目标

使用 Three.js 制作一款完整、精致、原生运行于浏览器的 3D 平台游戏 **Star Course**。它以 **《超级马力欧 64》**广为人知的自由奔跑、类模拟摇杆手感、跟随相机、金币、敌人、移动平台、失误恢复和目标星星结构作为共同玩法参照。名称、角色设计、关卡几何、敌人、收集物、声音、纹理和界面资产都必须原创。

制作一条包含三个相连区域的紧凑关卡：草地起点、移动平台峡谷和小型山顶塔楼。玩家需要收集十二枚金币中的至少八枚，穿越关卡，击败或避开两名敌人，抵达山顶并取得目标星星。跌落会损失三条生命中的一条，并在最近检查点重生；生命耗尽则失败。

## 完成合同

只有同时满足以下条件，目标才算完成：

- 移动、相机、跳跃、平台、金币、敌人、检查点、生命、目标解锁、胜利、失败和重开全部可用。
- 关卡经过明确布局，能够被读成穿越三个不同空间区域的路线。
- 移动具有可控的加速、空中调整、可靠落地和符合角色平台游戏的反馈。
- 生产构建成功，并在两个规定视口完成了整条关卡。

不要在角色能从盒子跳到盒子后停下。必须继续做到路线设计、移动手感、相机、危险与进度共同形成完整关卡。

## 必需游戏系统

- 第三人称移动，包含加减速、角色朝向、斜坡处理、重力、落地判断、空中控制、可变跳跃高度，以及宽容的土狼时间或跳跃缓冲。
- 环绕跟随相机，具有碰撞或遮挡处理、手动调整和不会与玩家争夺控制的自动回正。
- 十二枚固定金币，具有拾取反馈、分数，并在当前生命期间保持收集状态。未收集至少八枚时，山顶星星不可取得。
- 至少三个路径可预测的移动平台，能够正确携带玩家，并避免穿透或瞬间挤压。
- 两名巡逻敌人，接触危险清晰，并提供踩踏或同类技巧型击败方式。
- 一种非致命环境危险、一处无底坠落区、三条生命，以及包含起点在内的至少两个检查点。
- 当前金币、生命、检查点反馈、星星条件、目标、胜利、失败和重开界面。
- 桌面键盘与指针控制，以及可用的手机移动、相机、跳跃和可选动作控制。

## 执行检查点

1. 建立角色控制器、碰撞、相机、响应式输入，以及贯通三区的灰盒路线。
2. 完成金币、敌人、危险、生命、坠落恢复、检查点、移动平台和目标条件。
3. 调整移动、相机、平台时序、敌人公平性、完整状态流和重开。
4. 用经过设计的几何、地标、材质、光照、粒子和清晰反馈取代灰盒感。
5. 在 1440 x 900 和 390 x 844 下完成关卡，测试所有检查点、移动平台、失去生命、缩放和胜利。

## 质量门槛

- 跳跃结果可以预测，相机能保持预期落点可见。
- 移动平台必须正确带动玩家，不能因缺失相对运动而明显滑动。
- 跌落或受伤后不能陷入反复立即死亡。
- 金币和星星条件表达清楚，少于八枚金币时不能胜利。
- 触摸控制保持稳定，并给玩家留下足够画面判断平台深度。

## 运行时检查合同

提供随游戏进程更新、可 JSON 序列化的 `window.__WEB3DGAMEBENCH__` 对象，至少包含：

- `phase`：`ready`、`playing`、`paused`、`won` 或 `lost`；
- `score`：有限数值；
- `player`：由有限数值组成的 `{ x, y, z }`；
- `coinsCollected`：0 到 12 的整数；
- `coinsTotal`：固定为 `12`；
- `lives`：0 到 3 的整数；
- `checkpoint`：非负整数；
- `enemiesDefeated`：0 到 2 的整数；
- `starUnlocked`：布尔值；
- `seed`：`73693`；
- `restartCount`：非负整数。

可以增加字段，但不得暴露只供评测器使用的捷径或可调用函数。

## 约束与最终证据

使用提供的 Three.js 依赖和起始工具链。运行时不得请求网络，不得获取额外包或外部资产。全部代码和生成资产必须保留在工作区内。`npm run build` 必须把静态生产构建输出到 `dist/`。完成前如实报告构建结果，以及桌面端和手机端完成整条关卡的试玩结果。
