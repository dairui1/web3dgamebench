# First Night / 初夜生存

## 目标

使用 Three.js 制作一款完整、精致、原生运行于浏览器的 3D 体素生存游戏 **First Night**。它以 **《我的世界》**广为人知的探索、破坏与放置方块、制作、搭建庇护所和昼夜生存循环作为共同玩法参照。名称、世界生成、几何、纹理、声音、生物、配方和界面资产都必须原创。

生成一座确定性的紧凑体素岛屿。玩家需要收集至少三份木材和三份石材，制作信标，搭建一个小型封闭庇护所，把信标放到屋顶，并存活到黎明。夜晚会出现两只敌对生物。只有信标已经放置且玩家熬过整夜才算胜利；因伤害死亡或跌出世界则失败。

## 完成合同

只有同时满足以下条件，目标才算完成：

- 玩家可以探索、选择方块、破坏并收集、放置方块、管理快捷栏、制作信标、搭建、战斗并抵达黎明。
- 种子世界是连贯可探索的场所，包含地形、资源、地标、边界和光照变化。
- `ready`、`playing`、`paused`、`won`、`lost` 与重开状态不会破坏库存或地形。
- 生产构建成功，并在两个规定视口完整试玩了从采集到黎明的流程。

不要在渲染出体素地形后停下。必须继续做到世界能够承载完整的生存与建造目标。

## 必需游戏系统

- 一座确定性的体素岛，平面范围至少 24 x 24 个方块，具有高度变化、泥土、石头、树木、水晶矿和清晰安全的出生区域。
- 第一人称或近距离第三人称移动，包含重力、跳跃、地形碰撞、落地判断，以及非致命坠落后的合理恢复。
- 基于射线的方块选取和可见高亮、耗时破坏、资源掉落、库存计数、在合法相邻面放置，并阻止方块放进玩家身体。
- 包含已收集方块类型的快捷栏，以及会准确消耗三份木材和三份石材的信标配方和清晰制作交互。
- 具有可读天空与光照变化的白昼、黄昏、夜晚、黎明循环。夜间恰好生成两只追击并伤害玩家、但不能隔墙攻击的敌对生物。
- 基础攻击、生命值、受伤反馈、资源计数、当前槽位、目标清单、时间指示与重开流程。
- 桌面键盘鼠标，以及可完成移动、视角、跳跃、破坏、放置、攻击、切槽和制作的手机控制。
- 最低输入约定：桌面端向前移动必须响应 W 或上方向键之一；手机端主要移动区必须位于屏幕左下控制区域。

## 执行检查点

1. 建立确定性体素生成、网格、移动、重力、碰撞、相机与响应式输入。
2. 完成选取、破坏、掉落、库存、快捷栏、放置规则和信标配方。
3. 完成昼夜时间线、敌对生物、战斗、庇护相关碰撞、胜负逻辑与重开。
4. 提升地形构图、材质、天空、光照、粒子、交互反馈与 HUD 清晰度。
5. 在 1440 x 900 和 390 x 844 下完整试玩采集、制作、搭建、防守和黎明流程。

## 质量门槛

- 玩家始终知道目标方块、刚获得的资源、当前选择和剩余任务。
- 方块破坏与放置能一致修改世界，不能留下不可见碰撞。
- 生物应能威胁暴露在外的玩家，但墙体能提供有意义的保护。
- 信标未制作前不能放置；仅仅等到黎明不能触发胜利。有效庇护所必须至少包含两个水平相邻、可站立的内部格，每格上方都有两格空气净高；玩家放置的实体墙必须在身体高度将其与外部隔开，顶部也必须由玩家放置的屋顶方块覆盖。信标必须由这片屋顶直接支撑。只按放置方块数量设置布尔值不算有效空间封闭检测。
- 重开必须恢复原始种子地形、库存、信标、庇护所、生物、生命值和时间状态。
- 触摸控制无需悬停、右键或实体键盘即可完成整个目标。

- 两个评测视口的页面横向溢出都不得超过 2 个 CSS 像素，受测流程不得产生未捕获页面异常或 `console.error` 输出。

## 运行时检查合同

提供随游戏进程更新、可 JSON 序列化的 `window.__WEB3DGAMEBENCH__` 对象，至少包含：

该对象从首个渲染帧起就必须字段完整并通过 schema，开始前反映可玩的初始状态；重新开始后，除 `restartCount` 外必须回到同一状态。游玩中按 `R` 必须立即重新开始，手机模式必须提供文本、`aria-label` 或 title 明确写有“重开”或“Restart”的可见控件；任一路径都只让 `restartCount` 增加一次。

- `phase`：`ready`、`playing`、`paused`、`won` 或 `lost`；
- `score`：有限数值；
- `player`：由有限数值组成的 `{ x, y, z }`；
- `health`：0 到 100 的有限数值；
- `timeOfDay`：0 到 1 的有限数值；
- `inventory`：由非负整数构成的 `{ wood, stone, crystal }`；
- `selectedSlot`：非负整数；
- `blocksBroken`：非负整数；
- `blocksPlaced`：非负整数；
- `beaconCrafted`：布尔值；
- `beaconPlaced`：布尔值；
- `shelterValid`：布尔值；
- `shelterCellCount`：非负整数，表示通过上述封闭检测的可站立内部格数量；
- `dawnReached`：布尔值，仅在昼夜循环实际进入黎明后变为 true；
- `hostilesAlive`：0 到 2 的整数；
- `seed`：`37199`；
- `restartCount`：非负整数。

可以增加字段，但不得暴露只供评测器使用的捷径或可调用函数。

## 约束与最终证据

使用提供的 Three.js 依赖和起始工具链。运行时不得请求网络，不得获取额外包或外部资产。全部代码和生成资产必须保留在工作区内。`npm run build` 必须把静态生产构建输出到 `dist/`。完成前如实报告构建结果，以及桌面端和手机端一次成功熬过整夜的完整试玩结果。
