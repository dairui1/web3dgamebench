# Canyon Strike / 峡谷突袭

## 目标

使用 Three.js 制作一款完整、精致、原生运行于浏览器的 3D 游戏 **Canyon Strike**。它应当是一段原创的街机式空战任务，并以 **《皇牌空战》**广为人知的第三人称飞行、目标锁定、导弹攻击和任务推进作为共同玩法参照。不得复制其名称、飞机、故事、地图、界面美术、音频或其他受保护资产。

玩家需要穿越山地峡谷，摧毁三个地面火力点和两架拦截机，最后穿过撤离门。只有全部目标被摧毁并完成撤离才算胜利；战机被击毁、以致命速度撞上地形或任务倒计时结束均算失败。

## 完成合同

只有同时满足以下条件，目标才算完成：

- 游戏具备任务简报或开始状态、可完整游玩的任务、明确的胜负状态和快速重开。
- 飞行、武器、敌人、目标进度、伤害、碰撞、计时和撤离都是真实可用的系统，而非装饰。
- 生产构建成功，并在两个规定视口完整试玩了从开始到结算的闭环。
- 成品应像一段经过编排的空战任务，而不是在零散几何体上方自由飞行。

不要停在“已经能玩”的第一个原型。必须继续完成手感、信息可读性、响应式控制和最终验证。

## 必需游戏系统

- 具有稳定地平线参照和明确速度感的第三人称追尾相机。
- 俯仰、偏航、滚转、油门、有限加速度，以及与帧率无关的运动。
- 连发机炮和数量有限的锁定导弹；制导导弹发射前必须有可见锁定过程。
- 三个可区分的地面目标和两架拦截机，并具有可读的攻击或规避行为。
- 由地形、峡谷壁、路线地标、目标布置和撤离门组成的连贯任务路线。
- 生命值、受击反馈、武器冷却或弹药、任务计时、目标计数、雷达或目标方向提示，以及当前目标。
- 桌面端键盘控制，以及可用的手机控制，例如虚拟飞行摇杆、武器键和油门控制。
- 页面失去可见性时暂停。音频可选，但只能在用户交互后开始。

## 执行检查点

1. 建立峡谷、飞机控制器、相机、碰撞，以及桌面和手机输入。
2. 完成两种武器、锁定逻辑、全部敌人、生命值与任务状态转换。
3. 完成目标序列、撤离条件、HUD、反馈与重开流程。
4. 提升空间构图、光照、特效、敌人辨识度和速度感。
5. 在 1440 x 900 和 390 x 844 下构建并完整试玩，修复运行错误、遮挡、空白画面和无法通关的问题。

## 质量门槛

- 飞机和目标在环境中能被立即辨认。
- 操控可控、碰撞公平，相机不会制造不必要的方向混乱。
- HUD 能传达关键任务信息，同时不遮挡飞行路线。
- 胜利必须依次完成规定动作，不能靠等待或调试捷径触发。
- 页面缩放不能重置任务或破坏输入。

## 运行时检查合同

提供随游戏进程更新、可 JSON 序列化的 `window.__WEB3DGAMEBENCH__` 对象，至少包含：

- `phase`：`ready`、`playing`、`paused`、`won` 或 `lost`；
- `score`：有限数值；
- `player`：由有限数值组成的 `{ x, y, z }`；
- `health`：0 到 100 的有限数值；
- `missiles`：非负整数；
- `targetsDestroyed`：0 到 5 的整数；
- `targetsTotal`：固定为 `5`；
- `missionSecondsRemaining`：非负有限数值；
- `seed`：`19031`；
- `restartCount`：非负整数。

可以增加字段，但不得暴露只供评测器使用的捷径或可调用函数。

## 约束与最终证据

使用提供的 Three.js 依赖和起始工具链。运行时不得请求网络，不得获取额外包或外部资产。全部代码和生成资产必须保留在工作区内。`npm run build` 必须把静态生产构建输出到 `dist/`。完成前如实报告构建结果，以及桌面端和手机端的试玩结果。
