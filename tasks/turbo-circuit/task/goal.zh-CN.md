# Turbo Circuit / 涡轮巡回赛

## 目标

使用 Three.js 制作一款完整、精致、原生运行于浏览器的 3D 街机卡丁车游戏 **Turbo Circuit**。它以 **《马力欧赛车》**广为人知的彩色环形赛道、漂移加速、道具拾取、对手赛车、圈数、排名和冲线结构作为共同玩法参照。名称、角色、卡丁车、赛道、道具设计、声音、纹理和界面资产都必须原创。

制作一条封闭赛道，共三圈、三名 AI 对手、至少八个检查点、两条捷径或替代线路、越野减速、加速板和道具门。玩家必须完成比赛；最终排名决定结果，第一名视为胜利，其他名次视为已完成但失败，并可立即重开。

## 运行完成合同

以下功能清单定义目标作品与质量评测标准，不要求 Agent 为每一项做穷尽式自证。满足以下运行检查后即可完成 Goal：

- `npm run build` 成功，并把静态生产构建输出到 `dist/`。
- 生产构建能在 1440 x 900 和 390 x 844 下加载，显示可见、非空白、可交互的 3D 场景；受测流程的横向溢出不超过 2 个 CSS 像素，且没有未捕获页面异常或 `console.error`。
- 每个视口各做一次简短冒烟检查，确认游戏可以进入主要游玩状态、一个主要控制会改变可观察的游戏状态，并且重开能返回有效初始状态。

检查必须保持短时且有界。只有检查失败并完成相关修复后才重跑，通过后立即停止。不要为了证明完成而编写自动驾驶器，也不要反复跑完整胜利、失败、任务、对局、比赛、营业、整夜、关卡、任务链、Boss 战或解谜流程。这些路径以及功能完整度、平衡、打磨和游戏手感由提交后的评测决定；不足会影响结果，但不要求 Agent 在运行检查通过后继续自测。只报告实际执行过的检查。

## 目标游戏系统

- 追尾相机下的卡丁车操控，包含加速、最高速度、刹车或倒车、随速度合理变化的转向、侧向抓地、碰撞反馈和与帧率无关的物理。
- 按住并释放的漂移操作，具有可见蓄力阶段，以及强度与成功漂移时间相关的短暂加速。
- 一条连续三圈赛道，包含至少八个顺序检查点、逆行检测、圈数验证、护栏或恢复、越野减速和两条有意设计的替代线路或捷径。
- 三辆外观不同的 AI 赛车，使用相同赛道进度，具有速度差异、障碍恢复、基础避让，并且除明确卡死恢复外不能瞬移。
- 道具门应在一场完整比赛中确定性地提供两种持有道具：向前速度爆发和放置减速区域。HUD 显示当前道具并提供明确使用控制；高质量的完整比赛应支持至少各使用一次。
- 至少两个加速板、碰撞和超车反馈、实时排名、圈数、检查点方向、速度、漂移蓄力、道具、比赛计时、倒计时、冲线结果和重开界面。
- 桌面键盘控制，以及可用的手机转向、油门、刹车、漂移和道具控制。
- 最低输入约定：桌面端加速必须响应 W 或上方向键之一；手机端油门必须是位于屏幕右下控制区域、可持续按住的可见控件。

## 执行检查点

1. 建立赛道、车辆控制器、追尾相机、碰撞、检查点、圈数、响应式输入和道路恢复。
2. 完成漂移蓄力与加速、越野、加速板、道具和清晰驾驶反馈。
3. 完成三名 AI、排名、开赛倒计时、冲线顺序、胜负和重开。
4. 提升赛道地标、几何、光照、材质、粒子、车辆动画、速度反馈和 HUD 可读性。
5. 最后一次相关修改后执行一次构建，再在 1440 x 900 和 390 x 844 下完成有界运行冒烟检查。只需在完成前修复实际观察到的构建、启动、空白画面、输入、重开、异常或布局故障。

## 质量目标

- 圈数不能通过在同一检查点反复倒车，或跳过顺序路线推进。
- 漂移必须改变操控并产生挣得的加速，而不是常驻加速按钮。
- AI 不能永久卡住，也不能无视赛道规则。
- 玩家若保持不动，或整场没有挣得一次漂移加速，必须至少输给一名对手；AI 配速不能成为静止不动或刻意弱化的送分条件。
- 在比赛速度下仍能读清赛道方向和下一处弯道。
- 触摸控制保持固定和可触达，不能遮挡排名、圈数或近处道路。

- 两个评测视口的页面横向溢出都不得超过 2 个 CSS 像素，受测流程不得产生未捕获页面异常或 `console.error` 输出。

## 运行时检查合同

提供随游戏进程更新、可 JSON 序列化的 `window.__WEB3DGAMEBENCH__` 对象，至少包含：

该对象从首个渲染帧起就必须字段完整并通过 schema，开始前反映可玩的初始状态；重新开始后，除 `restartCount` 外必须回到同一状态。游玩中按 `R` 必须立即重新开始，手机模式必须提供文本、`aria-label` 或 title 明确写有“重开”或“Restart”的可见控件；任一路径都只让 `restartCount` 增加一次。

- `phase`：`ready`、`countdown`、`playing`、`paused`、`won` 或 `lost`；
- `score`：有限数值；
- `player`：由有限数值组成的 `{ x, y, z }`；
- `lap`：1 到 3 的整数；
- `checkpoint`：非负整数；
- `rank`：1 到 4 的整数；
- `speed`：非负有限数值；
- `driftCharge`：0 到 1 的有限数值；
- `driftBoostsEarned`：非负整数；
- `heldItem`：`boost`、`slow-field` 或 `null`；
- `boostItemsUsed`：非负整数；
- `slowFieldsUsed`：非负整数；
- `finishCrossed`：布尔值，仅在玩家通过已验证的最后一圈终点线后变为 true；
- `raceSeconds`：非负有限数值；
- `seed`：`82939`；
- `restartCount`：非负整数。

可以增加字段，但不得暴露只供评测器使用的捷径或可调用函数。

## 约束与最终证据

使用提供的 Three.js 依赖和起始工具链。运行时不得请求网络，不得获取额外包或外部资产。全部代码和生成资产必须保留在工作区内。`npm run build` 必须把静态生产构建输出到 `dist/`。完成前如实报告生产构建结果和两个视口的有界冒烟检查。无需也不要求提供完整胜负或端到端通关证据。
